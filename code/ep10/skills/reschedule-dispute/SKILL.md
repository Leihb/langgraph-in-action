# 超窗改期例外处理

客人要求的改期已经超过 `get_policy` 里 reschedule 那条政策规定的免费窗口，
按默认规则应该拒绝。这份说明书给的是"要不要破例"的判断依据，不是让你
绕开政策乱开口子。

## 先确认三件事

1. 用 `get_order` 查清楚出行日期，用 `get_policy` 查清楚这个商品的
   reschedule 窗口，算清楚客人现在到底超了几天——超 1 天和超 20 天，
   处理方式不一样。
2. 客人有没有提供可核实的理由：住院证明、护照/签证问题、政府通知的
   不可抗力。空口说"有急事"不算。
3. 这个订单的出行日期是不是已经过了——已经过了出行日的订单不适用这份
   说明书，直接按订单已完成处理，不要往下走。

## 什么情况可以破例

超窗不超过 3 天，且客人提供了具体理由（不用要求上传证明，客人说清楚
理由即可）：可以在回复里明确说"这是一次性的特殊处理"，然后正常按
改期流程走。

超窗超过 3 天，或者客人说不清楚具体原因：不要破例，按政策原文回复，
可以引导客人走退款流程（如果退款政策允许）。

## 回复的措辞

破例的时候一定要说清楚"这是一次性特殊处理，不代表以后超窗也能改"——
不说这句话，客人会以为这是新规矩，下次带着这次的对话记录来据理力争。
